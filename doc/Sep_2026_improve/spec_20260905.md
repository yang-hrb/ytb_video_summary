## 1. 背景与目标

本 repo 现在是个“大而全”的个人效率工具：YouTube / Podcast / 本地 MP3 / Dashboard / Watchlist / 日报全都有。但实际只用 **YouTube Playlist 的下载 + Summary + Daily Digest + GitHub 上传**，外加偶尔丢个本地 MP3 文件夹进来转写。

目标：砍到只剩这条主链，修掉跨天、去重、自动化三个真痛点，让 Hermes Agent 能 автономно 跑起来。

## 4. 去重索引库（新 DB）

### 4.1 选型

* 新库：`logs/ytb_summary_track.db`，单表 `videos`。
* 旧库：`logs/run_track.db → logs/run_track_backup.db`，COMPLETED 按新格式一次性导入（冷启动全重跑烧不起 OpenRouter 的钱，必须导）。
* 口径唯一：以后“做没做过”只查新库，不查旧库。旧库只留作备份，不再写入。

### 4.2 表结构

```sql
videos(
  video_id TEXT PRIMARY KEY,   -- YouTube: 11 位 video_id；本地: local_<sha256[:16]>
  url TEXT NOT NULL,
  channel_url TEXT,
  publish_date TEXT,           -- ISO，如 2026-09-01
  first_seen TEXT NOT NULL,    -- 首次发现时间
  md_path TEXT,                -- 本地 MD 路径
  github_url TEXT,
  status TEXT NOT NULL,        -- COMPLETED / FAILED / PENDING_KILLED
  fail_count INTEGER DEFAULT 0,
  last_error TEXT,
  updated_at TEXT NOT NULL
)
```

### 4.3 去重语义

* YouTube 主键 = `video_id`；本地 MP3 主键 = `local_<sha256(文件内容)[:16]>`（不用随机 UUID，不用文件名；改 1 字节才算新文件），`url` 字段存原始 `folder/filename.mp3`。
* 命中 COMPLETED：**Digest 里贴旧 MD 路径引用，GitHub 零新增**（防 review M5 说的仓库撑爆）。
* 新增 `--force / --no-reuse`：复用时打印报告路径 + 生成时间，让“跳过”可见（修 review H2）。

## 5. 自动化（每天 04:00）

* 清单文件：repo root `channellist.txt`，一行一个 **channel URL**，跳空行和 `#` 注释，用户手维护。
* 频率：`crontab` 每天 04:00 一次，全程约 2 小时，代码内 `--max-hours 4` 自己计时停（不用系统 `timeout`，否则半成品 Digest 发不出）。
* 范围：只看 `published` 最近 2 天的视频（`upload_date` 拿不到时回退 `published_parsed`，都没有则算“旧”不跑，避免漏跑判断失控）。
* 顺序：扫 TXT → 查新库 → 只跑没 COMPLETED 的 → 跑 pipeline → 生成 Daily Digest → 传 GitHub。
* 鉴权：`.env` 供 `OPENROUTER_API_KEY / GITHUB_TOKEN / GITHUB_REPO`，现有方式不变。
* 超时 kill 语义：算“没跑过”（`fail_count` 不加，`status=PENDING_KILLED`），Digest 照发，未跑的列出来。
* `channel_watcher` 必须修（review H6）：FAILED 不自动重跑、连接复用一次、预热对齐 `batch.py`、`playlistend=15` 改为“2 天窗口”。

## 6. Daily Digest（含跨天 + 两次失败）

### 6.1 跨天语义

* Digest 日期 = **启动日**（04:00 那次），文件名/标题都用它。哪怕跑到 06:30 甚至第二天，整个 job 进同一个 Digest，不再按每个视频的 wall clock 散写。
* `daily_summary` 必须修（review H7）：直接读新库 `uploader/title/duration` 列，不再靠文件名 `split('_')` 猜；补 `duration` 恒 0 的坑。

### 6.2 Digest 结构

1. 顶部红区：`two_time_fail`（见 §6.3）+ `fail_count`、错误原因；
2. 本次新增：新跑出的 MD 列表；
3. 引用复用：去重命中的旧 MD 路径列表（零新增）；
4. 未跑：`PENDING_KILLED`（超时）列表，下次静默重跑。

### 6.3 两次失败

* fail 下次重跑，`fail_count` 记在新库。`fail_count=2` 时写 `logs/two_time_fail.txt`，格式：
  `video_id,url,第一次失败时间,第二次失败时间,错误`
* 同时当天 Digest 顶部标红 + 失败原因。“告诉我”= 看文件 + 看 Digest，不另加邮件。

## 7. Agent-friendly（Hermes）

* 参照 `full_auto_run_playlist.sh:167` 那行包三入口，Agent 必须都会：
  1. `python src/main.py -video <url> --style detailed --cookies cookies.txt --upload`
  2. `python src/main.py -list <playlist_url> ...`
  3. `python src/main.py --scan channellist.txt ...`（扫 channel 自动找新视频）
  4. `python src/main.py -local <mp3_folder> ...`（需给本地 MP3 folder path）
* 重写 `AGENTS.md`（给通用 Agent；如需 Hermes 专用再加 `SKILL.md`），必须包含：venv 路径、`.env` 读取、四条 CLI 例子、新库表结构、失败去哪看（`logs/two_time_fail.txt` + Digest 红区）、`yt-dlp` 手动升级句。
* 本地 MP3 进新库（见 §4.3 hash 主键），Agent 跑 `-local` 时同样先查库。
